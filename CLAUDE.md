# Prepper

An interview-prep web app that renders the Obsidian vault in `content/` as a linked,
navigable library with practice in place. The repo is a **Quartz clone** with the vault
inside it ([ADR 0002](docs/adr/0002-quartz-as-the-build-pipeline.md)).

## Where code goes

Quartz upstream is a **git remote, merged periodically, never edited in place**. All of
our code lives under [`prepper/`](prepper/README.md) and reaches Quartz through
`quartz.config.yaml`. Four files outside `prepper/` are ours to edit —
`quartz.config.yaml`, `package.json` (scripts and dependencies), `.prettierignore`, and
`content/` — and nothing else is. See [`prepper/README.md`](prepper/README.md).

The merge procedure is [`docs/upstream-merges.md`](docs/upstream-merges.md).

`docs/` holds Quartz's own documentation vault as well as ours. Ours is `docs/adr/`,
`docs/agents/`, and `docs/upstream-merges.md`.

## Commands

| Command            | What it does                                                                |
| ------------------ | --------------------------------------------------------------------------- |
| `npm run build`    | Emit the site from `content/` into `public/`.                               |
| `npm run serve`    | Build and serve with live reload.                                           |
| `npm test`         | Upstream's suite plus ours.                                                 |
| `npx tsc --noEmit` | Typecheck.                                                                  |
| `npm run ulid`     | Mint a ULID. Record identity is **generated by running this, never typed**. |

## Testing

Almost everything is asserted through **seam 1**, `build(fixtureVault) → emitted site`:
a test states a fact about Markdown that goes into a vault and a fact about the site that
comes out. The harness is
[`prepper/testing/build-fixture.ts`](prepper/testing/build-fixture.ts); fixtures are small
purpose-built vaults, one per behaviour cluster, described in
[`prepper/testing/fixtures/README.md`](prepper/testing/fixtures/README.md).

Test external behaviour, never implementation. A test that asserts which plugin ran, in
what order, or what an intermediate mdast node looked like, will break on the next
upstream merge for no reason.

## Research output

`/research` writes its notes into `content/research/`, named after the **question** they
answer rather than the topic they touch, so they never collide with the Term or Lesson of
the same name. Research notes are Workshop: they stay in the vault, the reader never sees
them, and they are never pruned after a Reference distils them.
