Hash map complexity

Hash Maps Big-O lesson · 6 min

Read first

✓ Arrays  ·  ✓ Big-O notation  ·  ○ Hashing — unread

A hash map trades space for time. The key is run through a hash function to produce an index into a backing array, so the average lookup touches exactly one slot — no scan, regardless of how many keys the map holds. This is the whole reason Hash Maps displace Arrays for membership tests.

Average case, not worst case. The worst case is what Collision handling exists to bound.

The catch is that "one slot" assumes the hash spreads keys evenly. When two keys land in the same bucket the map falls back to scanning that bucket — and in the degenerate case where every key collides, lookup degrades to linear.

m = {}
m["ford"] = 1     # hash("ford") -> bucket 7
m["ford"]         # hash again -> bucket 7, one probe
Retrieval practice

A hash map lookup, average case, costs what?

✓ The key hashes straight to its bucket.

✗ Nothing is scanned unless buckets collide. → Collision handling

✗ That is an unsorted array, not a hash map.

Resizing

Once the load factor crosses its threshold the map allocates a larger backing array and rehashes every key. That single insert is O(n) — but it happens rarely enough that inserts amortise to O(1), the same argument that makes a dynamic array's push cheap.

Deletion in an open-addressed map cannot simply blank the slot, or it severs the probe chain behind it; the slot is marked with a tombstone instead.

Cloze

Resizing rehashes every key, which is why a single insert can cost O(n).
