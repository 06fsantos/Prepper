# Prepper — wayfinder map

Labels: `wayfinder:map`

## Destination

A written spec for **Prepper**: a software-engineering interview-prep web app that renders a Markdown vault as a linked, navigable library with in-place practice. Content is authored offline by the dev running `/author` and `/research` in the terminal; the app never invokes an agent and stores no per-user state. The spec is ready to hand to `/to-spec` and `/to-tickets`.

## Spec

**Written**: [Prepper — spec](spec.md). All twenty tickets resolved; the destination is reached. Label: `ready-for-agent`.

## Notes

**Domain**: interview preparation; personal knowledge management; static site generation from an Obsidian-compatible Markdown vault.

**Skills every session should consult**: `grilling` and `domain-modeling` by default. `research` for AFK fact-finding tickets. `prototype` for the look-and-feel tickets. `codebase-design` once module seams are on the table.

**Standing decisions for this effort** (settled while charting, do not relitigate without cause):

- The content pipeline is **author-only**. The dev runs the skills locally, they write Markdown into `content/`, the dev commits. No in-app agent execution, no API keys held by the app.
- `content/` is an **Obsidian vault inside the app repo**. Markdown is the stored form, `[[wikilinks]]` are real links, HTML is only ever a rendered output.
- **Build-time rendering.** Wikilinks resolved and the backlink graph computed once at build. Static deploy.
- **Fenced ```quiz blocks** carry in-lesson retrieval practice — valid Markdown, degrades to a code block in Obsidian, answered in place and never recorded.
- **No scheduler, and no stored state.** Practice is ad-hoc: the dev browses, picks what to study, and answers quiz blocks or attempts problems in place. Nothing is queued, scheduled, or recorded. Spaced repetition is out of scope for this map (see below).
- **The app is a read-only library.** Every screen derives from `content/`, so the build is a pure function of the vault and there is no client-side persistence layer.
- **Curated problem corpus**, imported from real sources — never invented by an agent. Invented interview problems have a known failure mode: plausible questions with subtly wrong or unverifiable answers. *Amended by [Problem authoring skill](issues/16-problem-authoring-skill.md)*: that rationale is about **invented** questions and does not reach an imported one, so the agent **may not invent problems** but **may author solutions to real, externally-sourced ones**. The dev still decides what gets imported.

- [Vault structure and note schema](issues/01-vault-structure-and-note-schema.md): six note types in two classes — `lesson`/`reference`/`problem`/`term` are Library content, `record`/`mission` are learner state. **Type is the directory, topic never is** (topic is many-to-many, so it lives in frontmatter as a controlled vocabulary naming `term` notes); consequently there is no `type` field. **Two identities**: filename for links, an immutable frontmatter ULID as a stable record anchor — see [ADR 0001](../../docs/adr/0001-split-note-identity.md). An unwritten link **warns and renders as a marked affordance**, and is carried as a placeholder node so the build can rank unwritten notes by inbound links. **Edges are typed by the field they sit in, never by inline syntax** — `prerequisites`, `topic`, the new `practices` field on problems, and untyped body links; the prerequisite graph must be a DAG. Infostring is ```` ```quiz <ULID> [type] ````; **identity is a hand-written ULID**, matching ADR 0001, since ordinal identity re-dates records on insert and hash identity orphans them on a typo fix. **Three types ship** — mcq, cloze, recall; code completion deferred. Consequence for ticket 11: the fence body must be **re-parsed as Markdown** with the wikilink transform running inside it, so a raw-string fence handler is not enough.

- [Vault search](issues/15-vault-search.md): **Quartz's search is adopted whole in mechanism; what changes is what lands in the index.** All five Library types indexed with no type-level exclusions — Workshop is out structurally, by never rendering. The decisive fact: `contentIndex.json`'s `content` field is the **rendered tree flattened** (`description` sets `file.data.text = toString(tree)`), so **anything the app renders is searchable, including what it visually conceals**. Making the index differ from the page therefore means recomputing `file.data.text` in **our own htmlPlugin ordered after `description`** — never mutating the tree, which would strip content off the page too. That plugin strips quiz material **per type** (mcq: options and explanations; cloze: spans reduced to surface text; recall: the reveal). **Sealed Problem sections stay indexed** — findable, because a solution is often the richest prose on a topic — and the spoiler is handled at render: the excerpt is suppressed for `problems/` results, and **solution sealing becomes pure CSS** so it survives injection into the search preview pane, which fetches a result's real HTML. **`topic` is copied to `tags` at build to feed search and nothing else**: `tag-page` stays disabled, since [ticket 02](issues/02-wikilink-resolution-and-backlink-graph.md) already made the Term page the canonical topic index and a second one would compete. **Results carry a type chip** derived from the slug — free, since type is the directory. The search component is **vendored**, not forked or patched, setting the precedent that core Quartz stays a remote while altered community plugins come in-tree — a distinction [ADR 0002](../../docs/adr/0002-quartz-as-the-build-pipeline.md) predates. Amends [Problem bank note format](issues/06-problem-bank-note-format.md) (CSS-only solution sealing), hands [Vault validation rules](issues/13-vault-validation-rules.md) one error (authored `tags`), and constrains [Quiz fence re-parsing under Quartz](issues/17-quiz-fence-under-quartz.md) (fence type must stay recoverable at html-plugin time, not just at parse time).

- [Problem authoring skill](issues/16-problem-authoring-skill.md): **`import`, a separate skill**, not a mode of `author` — `author`'s ~60% inherited teaching philosophy (ZPD, fluency vs storage strength) fires nowhere in "add these fifteen"; shared vault mechanics live in FORMAT docs instead, and `import` ships `PROBLEM-FORMAT.md` and **never sets `draft`**. **Amends the map's standing decision**: the ban is on agent-*invented* problems, not agent-authored solutions to real, externally-sourced ones — without which the dev hand-writes hundreds of solutions to problems they are importing precisely because they have not done them yet. **Two kinds of three**: `coding` and `system-design`; **behavioural is hand-authored** against the template, stated explicitly in `PROBLEM-FORMAT.md` so the gap reads as a decision. **Batch-shaped and safe to re-run**: takes a list, one note at a time, **halts on the first problem it cannot identify** (a hallucinated prompt is the only failure mode that poisons the vault silently), **duplicates skipped and reported** on `source` URL then title, never overwritten. The agent writes the paraphrased `## Prompt` (stating *what* is asked, never *how* — a leaked approach is a spoiler in an unsealed section), `## Solution`, `## Complexity`, optional `## Hints`, assigns `difficulty` (copying the source's label verbatim), and fills `topic`/`practices`, **minting missing `term` stubs** as `author` does — refusing would re-impose through the back door the constraint [ticket 06](issues/06-problem-bank-note-format.md) removed through the front. **Solutions are C#**, one language vault-wide; the repo's TypeScript is **irrelevant** — build stack and interview language were kept apart deliberately, the same unexamined-assumption trap [ticket 08](issues/08-static-site-tooling-for-obsidian-vaults.md) fell into. **Review is informal** — the dev reads the diff; `draft: true` and per-problem approval both declined, and dropping the behavioural kind removed the one case that structurally needed a flag. **Accepted risk**: execution verification was agreed then deferred, so nothing structural stands between a subtly-wrong solution and a commit — deliberate and reversible. **No coverage report or authoring queue** — the dev drives; the problem→lesson direction still runs automatically through unwritten-link ranking. Graduated [How `import` obtains a problem's text](issues/20-prompt-acquisition-for-import.md), which the halt rule presupposes.

- [Quiz fence re-parsing under Quartz](issues/17-quiz-fence-under-quartz.md): **yes, cleanly, no fallback** — [ticket 03](issues/03-quiz-block-schema.md)'s Markdown fence body survives whole and [ADR 0002](../../docs/adr/0002-quartz-as-the-build-pipeline.md)'s load-bearing assumption holds. **The worry's premise was wrong, and that is what makes it work**: Quartz v5 does not resolve wikilinks by text-level regex — `remark-obsidian` registers a **micromark syntax extension** producing real `wikilink` mdast nodes at parse time, converted to links by a separate tree transform. So the shape is neither the opaque-string mermaid pattern nor resolving wikilinks ourselves: **parse the fence body with Quartz's own parser and let the downstream transforms resolve it**. **Ordering is a first-class config field** (`order`, ascending, default 50; `builtinTransformers` is empty) — highlighting is 20, obsidian-flavoured-markdown is 30, so ours slots at **25** as a local-path plugin. **Syntax highlighting cannot interfere** — it is a *rehype* plugin, a phase later; the `excludeLangs` question was borrowed from Astro, whose highlighter runs at the wrong stage for us to have the problem. **Ticket 15's constraint holds**: `data.hProperties` carries `data-quiz-type`/`data-quiz-id` through to the hast element, which is Quartz's own `data-callout`/`data-clipboard` pattern. **Free win** — `crawl-links` walks the whole tree, so a wikilink in a quiz explanation becomes a real backlink-graph edge with no special-casing, satisfying [ticket 02](issues/02-wikilink-resolution-and-backlink-graph.md) as well as 03. **One hazard in source**: injected nodes carry fence-relative offsets and remark-obsidian's task-char transform slices the whole file, so stripping `position` fixes it at the cost of line numbers inside quiz bodies — appended to [Vault validation rules](issues/13-vault-validation-rules.md) as a message constraint, not a rule. Carry-forward: **pin the `quartz-community/*` refs** (read at HEAD, un-versioned `0.1.x`) and encode ticket 15's ordering as *greater than description's order*, never the literal 71. **Stated plainly: no build was run** — the citations are unambiguous but `self.parse()` yielding `wikilink` nodes should be the first thing the build spike proves, since a failure there falls back into ADR 0002.

- [Library-to-Workshop embed rendering](issues/18-library-to-workshop-embed-rendering.md): **degrade, and the choice was never live** — Quartz resolves non-media embeds **client-side**, fetching the target's *rendered page*, so publication requires a page and a Workshop note has none. [Ticket 11](issues/11-choose-static-site-tooling.md)'s accepted risk is **withdrawn, not mitigated**: it was priced on a build-time-inlining model Quartz does not implement, and rendering the transclusion would now be the expensive option (emitting hidden pages for Workshop notes). Decided on the criterion *easiest for the agent and the build*. **One rule for all of Workshop** — no `research`-vs-Learner-state carve-out, since [ticket 10](issues/10-research-output-into-the-vault.md) defined the class by renderability precisely to keep subject matter out of it. The free 404 degrades silently in the reader's browser, so the build **degrades it loudly instead**: converted to ticket 10's marked affordance in the same order-25 transform as [ticket 17](issues/17-quiz-fence-under-quartz.md), and an **error** where the Library→Workshop *link* stays a warning — a link at Workshop can be deliberate, an embed is always broken output. **The constraint lands on the skills, not the dev**: `author` picks **promote** (`/author reference`, whole-note — fragment promotion is not built) when the material is looked up repeatedly and stands alone, or **writes it into the Lesson** when it only supports that Lesson's argument — the vault's existing Lesson/Reference boundary, so no new concept, and `author`/`import` never emit such an embed. The reverse direction (Workshop embedding Library) is a **deliberate non-rule**. Amends [CONTEXT.md](../../CONTEXT.md) (three entries written on the wrong premise) and [ADR 0002](../../docs/adr/0002-quartz-as-the-build-pipeline.md); appends one error and one non-rule to [Vault validation rules](issues/13-vault-validation-rules.md). **Stated plainly: no build was run** — the client-side mechanism is cited from Quartz's docs, and the decision is robust either way, but it belongs in ticket 17's build spike.

- [How `import` obtains a problem's text](issues/20-prompt-acquisition-for-import.md): **recall-only, and the corpus scope is what makes it safe** — the two are one decision, not two. Browsing died on facts checked in-session (LeetCode 403s a plain fetch; neetcode.io returns an empty Angular shell), leaving it only as driving the dev's logged-in Chrome, **declined and recorded as declined**: it needs the dev present and permissioned, fails mid-batch, and makes the copyrighted prompt the agent's routine working material. - [Authoring feedback surface](issues/19-authoring-feedback-surface.md): the reports channel [ticket 13](issues/13-vault-validation-rules.md) split off gets a destination — the **Vault report**, a page **emitted by the build** at `/report`, plus a one-line terminal pointer per build (validation shouts, the report whispers). **A vault note was rejected on mechanism, not taste**: the build writing into `content/` inverts [ticket 05](issues/05-spaced-repetition-model.md)'s pure-function rule and closes a cycle — the report's own wikilinks would be counted as inbound edges and the queue would feed itself. **"A Library page that is not Library content" was a false problem**: it is not a note at all but emitter output, the category of `contentIndex.json` and the 404 page, so [ticket 02](issues/02-wikilink-resolution-and-backlink-graph.md)'s Library-only rendering rule is untouched and no class gains a carve-out. **Two sections, not three** — the axis is audience-in-time, which makes the empty-`term` backlog part of the *queue* (a note waiting to be written), not of hygiene: **authoring queue** (unwritten notes + empty Terms) and **vault hygiene**, one page, one trigger, cadence never a question. **Typed edges outrank untyped** in the ranking — [ticket 06](issues/06-problem-bank-note-format.md)'s required-but-satisfiable-unwritten `practices` pushed a committed obligation through the same counter as a passing mention — sorted typed-then-total with the breakdown printed, no weighting constant; and the breakdown is **navigation, not decoration**, since an unwritten note has no page and the row can only link to its inbound sources.
